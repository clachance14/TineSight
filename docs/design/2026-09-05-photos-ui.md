# Photo gallery and review layout

Implemented locally on September 5, 2026. Existing audit, authentication, landing-page and pipeline changes were preserved. This UI change has not been deployed.

## Design

The gallery borrows the restrained library controls of [Apple Photos](https://support.apple.com/en-gb/guide/photos/pht53854a251/mac); the review page follows the focused single-photo presentation documented in [Lightroom's Loupe view](https://helpx.adobe.com/vn_en/lightroom-classic/help/view-photos.html). These are layout references, not claims of feature parity. TineSight's dark palette and typography remain.

- One compact title row, primary Trophy bucks / All photos controls, and a popover for secondary groups. Score, sorting, full filters, saved views and selection remain accessible.
- All bucks is available in Other groups. Legacy `priority` links retain their original query semantics and show a notice; there is no combined trophy/security button or silently rewritten saved view.
- Photo review uses the full content width with a large contained image and adjacent metadata/detections on desktop. Mobile details collapse below the swipe viewer. Navigation and deletion follow the current photo.
- Removed the internal photo ID, duplicate detail heading row and image card padding. Zoom now uses the medium variant instead of the original URL.
- Virtualized, thumbnail-only rendering remains. Returning from a photo restores the grid offset within the current filter scope; changing filters resets it. The entire Photos page scrolls, with the title moving away and the filter toolbar pinning beneath the app header. The grid has no independent scroll area.

## Scrolling

Following the user's explicit refinement, the final gallery uses one page scroll owner (`main`). The virtualizer observes that element and measures the grid's offset within the page, including changes caused by filter controls and bulk selection. The toolbar uses CSS sticky positioning and pins flush beneath the app header. Photos continue behind it, and the title/saved-view row scrolls away.

The original grid was confined to 312px at 1280 × 800 and 260px at 390 × 844. The final page has no fixed-height photo window. Browser assertions confirm that only `main` scrolls in the normal gallery, the toolbar pins to its top, and the grid's overflow remains visible. Returning from a photo restores the page offset.

## Inline photo zoom

Photo review now zooms within its existing clipped image viewport. Removed the Zoom button, tap overlay and lightbox invocation from `PhotoDetailClient`. Wheel/pinch zoom is anchored to the cursor or pinch midpoint; mouse/touch dragging pans within the actual contained image edges. Double-click/double-tap toggles magnification, and focused keyboard controls support +/−, arrows and Escape/0. Image and detection overlays share the transform; page chrome and metadata do not. Medium variants remain the only displayed image source. Navigation mounts a fresh fitted photo. The pager cancels a pending swipe when a second finger starts a pinch.

Validation: `lib/photos/zoom.test.ts` covers anchor preservation, letterboxed pan bounds, reset and magnification limits. Full suite: 166 passing tests; type-check, scoped ESLint and production build pass. Existing keyboard/swipe acceptance passes. `scripts/triage-sim/zoom-acceptance.mjs` verifies wheel zoom without page movement, keyboard pan/reset, double-click and double-tap, synthetic pinch and touch pan without navigation, fixed browser scale, medium-only image sources and reset on next-photo navigation. Synthetic browser touches do not substitute for physical-device testing. Screenshots: `inline-zoom-desktop.png` and `inline-zoom-mobile.png` under `.gstack/triage-runs/photos-ui/`.

## Deer-details preview correction

The deer-details modal previously depended solely on a saved crop URL. A detection without a crop, or with a crop returning 404, displayed no image despite an available photo preview. The detection endpoint now supplies a separately signed medium/thumbnail `previewUrl` after its existing ownership check. The modal prefers the saved crop and falls back to framing the detection within that bounded variant, using center-based coordinates, actual image aspect ratio and context padding. The original image URL remains reserved for existing editing consumers and is not used in this small preview. Invalid coordinates fall back to the full bounded preview; unavailable images show an explicit status. Failure state is scoped to the detection and failed URL.

`node scripts/triage-sim/deer-preview-acceptance.mjs` passes five browser scenarios: missing crop, 404 crop, working saved crop, failed fallback, and phone layout. It performs real image-load checks against the isolated fixture server and restores changed fixtures afterward. Three crop-framing unit tests and new component/helper lint pass. Screenshots: `deer-preview-fixed.png`, `deer-preview-mobile.png`; results: `deer-preview-acceptance.json`. Full build compiles the application but remains blocked by unrelated TypeScript errors in the current processing jobs (first error: unused `GeminiMetrics` in `trigger/jobs/analyze-photo.ts`). Existing API/hook lint findings remain outside this fix.
