## Active-transfer cancellation follow-up

Root's actual browser experiment (`.gstack/triage-runs/simulator/cancel-active-state.json`) reproduced correct SQL cancellation but incorrect Bulk "Upload failed / signal is aborted without reason / Retry failed photos". Both upload modes now distinguish explicit user cancellation from account-change abort: cancelled unfinished File references leave the retry queue, completed references survive, the UI says "Upload cancelled", and retries against that cancelled run are not offered. The account-change path remains fenced from stale store updates.

Actual shared retry/store/panel regression tests exercise intentional cancellation, preserve a completed peer, ignore late failure callbacks, and require cancellation text without failed-photo retry. `node --test lib/upload/*.test.ts`: **39 passed**, `/tmp/tinesight-upload-cancel-tests.log`; typecheck passed. Scoped runtime lint is clean except the existing TanStack Virtual React Compiler compatibility warning on the unchanged virtualizer call (`/tmp/upload-cancel-lint.json`). Root owns browser re-verification after rebuilding.
