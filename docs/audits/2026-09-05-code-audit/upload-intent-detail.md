## Planning drift and superseded assumptions

- **Contradictory resume wording:** 012 spec edge case :97 says current duplicates uploaded, but later FR017 (:115), Phase1 note (:163) and final clarification (:175) require filename+size skip/reselection recovery. Use later explicit clarification. Persistent IndexedDB resume remains Phase2; its absence is not a Phase1 violation.
- **The unsafe filename-only DTO was already in the plan:** `012/research.md:229-234` returns filename arrays for filename+size matching. Multi-camera same-name behavior is a DESIGN gap as well as implementation drift. Request-level IDs are needed even if Phase1 still uses filename+size rather than content hashes.
- **Performance target impossible:** `012/spec.md:146` requires 30GB in <15min at 100Mbps. 30e9 bytes * 8 / 100e6 = 2400s = 40min, before overhead. 15min needs >=267Mbps sustained uplink. Rewrite target around throughput efficiency and realistic workload. 100Mbps must mean uplink, not advertised download speed.
- **Twenty-second discovery target has no prerequisites:** :144 cannot be an unconditional guarantee on rural links. A single 5MB file needs about 40 seconds at 1Mbps before AI; a 25-file chunk needs ~1000 seconds aggregate. All-files EXIF/dedup barrier further delays first transfer. Specify separate local-preparation, first-original, first-preview, and first-analysis latency budgets by connection/workload; stream earliest ready chunk.
- **Memory <500MB / 99% success / 95% recovery / <70min AI** (:145,147-149) are unverified goals, not established current capabilities. Provider limits/model/pipeline changed; avoid unsupported pass/fail numerics. Full-res Simple decode is a known implementation violation independent of benchmark.
- **Testing plan superseded:** 012 plan:15 and tasks:169-170 name Playwright/Vitest; tests are unchecked. Current CLAUDE.md + ADR0002 explicitly choose node:test and build/type-check/browser QA + budgets. Do not introduce forbidden old frameworks merely to check obsolete task boxes; restore meaningful end-to-end contract verification under current strategy.
- **Stack names stale:** old plan Next14/React18, account_id/photos/process-photo; actual app Next16/React19, user_id/images/analyze-photo. Mapbox replaced by Google Maps. Thumbnails now dedicated status-tracked variants ADR0003. Preserve intended behavior, not stale symbols.
- **Location granularity needs separating:** historical `batch` meant photos taken in one place; implementation's batch is network chunk. For dozens of cameras, treat import session, camera/deployment assignment, and transport chunk as separate concepts. Weekly re-import must preserve individual file identity, capture timestamp, historical location, and processing readiness across retries.
