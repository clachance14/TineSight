## T42 bounded metadata acceptance

Command: `node --experimental-strip-types --test lib/photos/service-regression.test.ts` — **33 tests passed**, approximately 8 seconds. This executes the current service through the installed Supabase query builder against a deterministic HTTP fixture responder that applies ordering/cursor/range predicates and enforces a 1,000-row response ceiling. It does not replace real PostgREST/browser acceptance.

| Metadata size | Null-score rows | Requests, ascending / descending | Maximum URL bytes, ascending / descending |
|---|---:|---:|---:|
| 1,001 | 112 | 28 /28 | 374 /376 |
| 1,200 | 134 | 30 /30 | 374 /376 |
| 10,000 | 1,112 | 214 /214 | 374 /376 |

Request counts include metadata pages, detection-count RPCs and complete select-all sweeps. Each fixture forces only five non-null score values, so tie groups cross page boundaries; every null tail is visited exactly once. Tests assert independent numeric/id tuple ordering, NULLS LAST in both directions, unique and complete IDs, eventual cursor exhaustion, first-page catalog total, page size≤100, identical select-all membership, and every emitted URL below 8,192 UTF-8 bytes with no image UUID IN list. The 2,001-source-batch case takes 4 requests/max 361 bytes, proves exact selected IDs and no source-batch prefetch/UUID filter.

Remaining boundaries: subsequent cursor-page `count` describes its filtered suffix; the grid intentionally takes catalog total from page 1. This acceptance does not measure real database query plans/latency, 10,000 decoded image memory, or behavior while rows mutate between requests. Static keyset pagination cannot guarantee snapshot membership when concurrent analysis changes sort scores; the client refresh policy handles eventual updates, not snapshot isolation. These are explicit limits rather than claims of a 100% production load simulation.

## Cancellation statistics consistency

Migration061 now excludes `images.is_cancelled = true` from both the image aggregates and joined detection aggregates in both `get_photo_stats` overloads (lines59/75 and120/138). It does not filter parent batch/session status: pending-only cancellation retains completed photos beneath a cancelled parent. Catalog/header statistics retain their existing archive-inclusive semantics; the active gallery can therefore legitimately have fewer photos than the global header after archiving.

Disposable PGlite regression in `scripts/verify-security-invariants.mjs` creates a cancelled parent containing two retained completed images (one archived), one cancelled pending image and one cancelled completed image with a detection. Before the fix the first overload returned4photos instead of2. After the fix both overload bodies report total2/analyzed2/pending0/bucks2/trophies2, preserving the archived retained child and excluding cancelled detection counts. Full security/upload/triage harness passes with `TINESIGHT_TEST_UPLOAD=1`.

Verification nuance: legacy default arguments overlap, making a direct SQL call with two positional UUID arguments ambiguous. The disposable harness temporarily renames the three-argument overload, executes both actual bodies as the authenticated owner, then restores its name. Production signatures/defaults remain unchanged; the mounted API sends three explicit arguments. Logs: `/tmp/tinesight-cancel-stats-red.log` and `/tmp/tinesight-cancel-stats-green.log`.
