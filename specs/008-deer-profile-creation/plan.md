# Implementation Plan: Deer Profile Creation

**Branch**: `008-deer-profile-creation` | **Date**: 2025-12-12 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/008-deer-profile-creation/spec.md`

## Summary

Enable users to create deer profiles from buck detections and view them on a dedicated detail page. Implementation requires: (A) fixing service layer schema mismatch (`account_id` → `user_id`), (B) creating the deer detail page with paginated sightings grid, and (C) adding "Create Deer Profile" CTA to the detection edit panel.

## Technical Context

**Language/Version**: TypeScript 5.x + Next.js 14 (App Router)
**Primary Dependencies**: React 18, TanStack Query, Zustand, shadcn/ui, TailwindCSS
**Storage**: PostgreSQL via Supabase (with RLS enabled)
**Testing**: Playwright (E2E), Vitest (unit) - integration tests for user journeys
**Target Platform**: Web (Vercel serverless)
**Project Type**: Web application (Next.js full-stack)
**Performance Goals**: Profile creation < 30 seconds (SC-001), page loads < 2s
**Constraints**: RLS required on all data access, dark mode default
**Scale/Scope**: Single user flows, ~100s of deer per account

### Task B: Create Deer Detail Page (P1)

**New Files**:
- `app/(dashboard)/deer/[id]/page.tsx` - Server component
- `app/(dashboard)/deer/[id]/deer-detail-client.tsx` - Client component

**Pattern**: Follow `app/(dashboard)/photos/[id]/page.tsx` structure:
- Server component handles auth, metadata, initial data fetch
- Client component handles interactivity (edit mode, navigation)

**Layout**:
```
Header: Back button + Deer name (editable inline)
Main (2/3): Reference detection image + notes (editable)
Sidebar (1/3): Sightings grid (paginated, 20 per page)
```

**Data Flow**:
1. Server fetches deer via `getDeerById()`
2. Pass to client component
3. Client uses `useDeer()` for mutations
4. Sightings rendered in paginated grid
