# Implementation Plan: SAM3 Vast Pipeline

**Branch**: `009-sam3-vast-pipeline` | **Date**: 2025-12-12 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/009-sam3-vast-pipeline/spec.md`

## Summary

Replace/augment Gemini-based deer detection with a SAM3-powered pipeline running on a Vast.ai GPU worker. The system uses text-prompted segmentation ("deer", "antlers") to produce bounding boxes and confidence scores. A feature flag enables switching between pipelines at deployment time. Implementation leverages existing Trigger.dev job patterns with a new `analyze-photo-sam3` job that communicates with the external GPU worker via HTTP.

## Technical Context

**Language/Version**: TypeScript 5.x, Python 3.11 (worker)
**Primary Dependencies**: Next.js 14, Trigger.dev v4, FastAPI, transformers, torch
**Storage**: PostgreSQL via Supabase (existing), Supabase Storage (images)
**Testing**: Playwright (E2E), integration tests for job pipeline
**Target Platform**: Vercel (serverless), Vast.ai (GPU worker)
**Project Type**: Web application with background job processing
**Performance Goals**: 30 seconds per photo, 15 minutes for 100-photo batch
**Constraints**: 60-second timeout per API call, >= 0.3 confidence display threshold
**Scale/Scope**: Thousands of photos per user per season

## Implementation Phases

### Phase 1: Database & Types

**Files to modify:**
- `supabase/migrations/011_sam3_detection_fields.sql` (CREATE)
- `types/database.ts` (UPDATE)

**Tasks:**
1. Create migration adding `analysis_source`, `antler_bbox`, `sam3_deer_score`, `sam3_antler_score` columns
2. Add indexes for filtering by analysis source
3. Backfill existing detections with `analysis_source = 'gemini'`
4. Update TypeScript types to include new fields
5. Run `supabase gen types` to regenerate types

### Phase 2: SAM3 Client Library

**Files to create:**
- `lib/sam3/client.ts`
- `lib/sam3/health.ts`
- `lib/config/feature-flags.ts`

**Tasks:**
1. Implement `Sam3Client` class with:
   - `analyzeImage(imageUrl, options)` → Detection results
   - `checkHealth()` → Worker status
   - Error handling with typed responses
2. Implement `Sam3HealthListener` class with:
   - WebSocket connection to `/ws/status`
   - Event-based status updates
   - Fallback to HTTP polling if WS unavailable
   - `waitForReady(timeoutMs)` → Promise that resolves when ready
3. Add `isSam3PipelineEnabled()` helper that reads env var

### Phase 3: Detection Service Updates

**Files to modify:**
- `lib/services/detections.ts`

**Tasks:**
1. Add `createSam3Detections(imageId, detections)` function
   - Similar to `createGeminiDetections()` pattern
   - Sets `analysis_source = 'sam3'`
   - Handles `antler_bbox` JSONB field
   - Converts pixel coordinates to 0-10000 normalized scale
2. Update `getDetectionsForImage()` to include new fields in response

### Phase 4: Trigger.dev Job

**Files to create:**
- `trigger/jobs/analyze-photo-sam3.ts`

**Files to modify:**
- `trigger/jobs/batch-process.ts`
- `trigger/index.ts`

**Tasks:**
1. Create `analyze-photo-sam3` job:
   - Same structure as `analyze-photo.ts`
   - Concurrency limit: 10 (GPU worker capacity)
   - Retry: 3 attempts, exponential backoff
   - Pre-dispatch: Wait for worker health via `Sam3HealthListener`
   - Call SAM3 worker API with signed URL
   - Insert detections via `createSam3Detections()`
   - Update image status (completed/failed)
   - 60-second timeout on worker API call
2. Update `batch-process.ts`:
   - Check `isSam3PipelineEnabled()` feature flag
   - Fan out to `analyze-photo-sam3` if enabled
   - Keep `analyze-photo` (Gemini) as fallback
3. Export new job from `trigger/index.ts`

### Phase 5: GPU Worker (Python)

**Files to create:**
- `sam3-worker/main.py`
- `sam3-worker/inference.py`
- `sam3-worker/health.py`
- `sam3-worker/requirements.txt`
- `sam3-worker/Dockerfile`

**Tasks:**
1. Implement FastAPI application with:
   - `GET /health` - Status and model state
   - `GET /ws/status` - WebSocket status stream
   - `POST /v1/analyze-image` - Main inference endpoint
2. Implement model loading:
   - Load `facebook/sam3` from Hugging Face
   - Cache to `HF_HOME` path for persistence
   - Broadcast status updates via WebSocket during warmup
3. Implement inference:
   - Download image from signed URL
   - Run SAM3 with text prompt "deer"
   - Run SAM3 with text prompt "antlers"
   - Match antler boxes to nearest deer boxes
   - Return structured response per API contract
4. Create Dockerfile for Vast.ai deployment
5. Document deployment steps in quickstart.md

### Phase 6: Integration & Testing

**Files to create:**
- `tests/integration/sam3-pipeline.test.ts`

**Tasks:**
1. Write integration tests:
   - Mock worker responses for CI
   - Test job creation and dispatch
   - Test detection record creation
   - Test error handling and retry
2. Manual testing:
   - Upload batch of photos with SAM3 enabled
   - Verify detections appear with correct source
   - Verify antler bounding boxes display
   - Test retry flow for failed photos
3. Performance validation:
   - Measure processing time per photo
   - Verify 100-photo batch completes in < 15 minutes
