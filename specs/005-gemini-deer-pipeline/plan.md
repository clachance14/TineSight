# Implementation Plan: Gemini Deer Analysis Pipeline

**Branch**: `005-gemini-deer-pipeline` | **Date**: 2025-12-09 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/005-gemini-deer-pipeline/spec.md`

## Summary

Migrate TineSight's deer detection pipeline from Replicate (MegaDetector + embeddings) to Google Gemini for vision-based analysis and deer re-identification. The new pipeline uses Gemini 2.5 Flash for:
1. **Bulk photo analysis** - Detect deer, extract species/sex/points/age, store head bounding boxes
2. **On-demand matching** - Compare new detections against named deer catalog using visual comparison

Key technical approach:
- Use `@google/genai` SDK with Zod schemas for structured JSON output
- Replace 3 existing jobs with 2 simpler jobs (analyze-photo, compare-deer)
- Remove embedding storage (pgvector) - Gemini performs direct visual comparison
- Fresh Start migration: clear existing detection data

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)
**Primary Dependencies**: Next.js 14 (App Router), @google/genai, Zod, Trigger.dev
**Storage**: PostgreSQL via Supabase (extended schema, no pgvector for new pipeline)
**Testing**: Playwright (E2E), Vitest (unit)
**Target Platform**: Vercel (serverless)
**Project Type**: Web application (Next.js full-stack)
**Performance Goals**: 1,000 photos in <15 minutes, <$0.25 per batch
**Constraints**: Gemini API rate limits, serverless function timeouts
**Scale/Scope**: ~50 batches/year, 1,000-5,000 photos per batch
